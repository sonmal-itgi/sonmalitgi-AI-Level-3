### 실시간 입력과 판정

| 사용 화면·범위 | 추론에 사용하는 최근 좌표 프레임 | 판정 간격(stride) | 판정 조건 |
|---|---|---|---|
| 유닛 5 평가: 운전/천천히(SEN0009)·운전/빨리(SEN0011)의 첫 단어 ‘운전’ | 8프레임 | 새 좌표 2프레임마다 | 목표 단어가 모델 점수 0.90 이상으로 3회 연속 |
| 위 두 문장의 두 번째 단어 ‘천천히’ 또는 ‘빨리’ | 최소 8프레임이 모이면 시작, 최대 12프레임 | 새 좌표 2프레임마다 | 목표 단어가 모델 점수 0.90 이상으로 3회 연속 |
| 유닛 5 평가: 가다/빨리(SEN0012)·시간/급하다(SEN0013)·약속/늦다(SEN0017) | 최소 16프레임이 모이면 시작, 최대 32프레임 | 새 좌표 2프레임마다 | 목표 문장이 모델 점수 0.90 이상으로 3회 연속 |
| 수어 사전: 운전·천천히·빨리 범위 | 최소 8프레임이 모이면 시작, 최대 12프레임 | 새 좌표 2프레임마다 | 같은 단어가 모델 점수 0.80 이상으로 2회 연속이면 후보 표시 |
| 수어 사전: 중급 단어 11개 범위 | 16프레임 | 새 좌표 2프레임마다 | 같은 단어가 모델 점수 0.80 이상으로 2회 연속이면 후보 표시 |
| 중급 단어 학습 평가 | 16프레임 | 새 좌표 4프레임마다 | 목표 단어가 모델 점수 0.50 이상으로 1회 |

- 표의 프레임은 **카메라 원본 영상 전체가 아니라 서버가 받은 손 좌표 시점**이다. 설정된 최대 크기만큼 최근 좌표를 유지하고 오래된 좌표를 버리는 슬라이딩 윈도우다.
- 웹은 좌표 전송 간격을 최소 125ms로 제한한다. 목표는 약 **8fps(초당 좌표 8개)**이며 실제 수신 속도는 기기·프레임 추출·네트워크·서버 응답에 따라 달라진다. 화면의 랜드마크 추출·그리기는 약 33ms 간격으로 별도 실행하며, 서버 응답 대기는 최대 2개 전송으로 제한한다.
- 8fps가 균일하게 유지된다면 stride 2는 약 0.25초마다 새 예측을 시도한다는 뜻이다. 실제 추론과 응답에 걸리는 시간까지 고정 0.25초라는 뜻은 아니다.
- 같은 8fps에서 첫 프레임~마지막 프레임 간격은 8프레임 약 0.875초, 12프레임 약 1.375초다. 수신 fps가 낮아지면 같은 프레임 수가 더 긴 시간을 포함한다.
- 선택한 윈도우는 전처리에서 **32타임스텝으로 리샘플링**한 뒤 LSTM에 넣는다. ‘최근 32프레임 수집’과 ‘모델 입력 32타임스텝’은 서로 다른 개념이며 리샘플링이 관측하지 않은 동작 정보를 추가하지는 않는다.
- 운전으로 시작하는 두 문장은 ‘운전 → 천천히/빨리’ 순서로 판정한다. 첫 단어가 확인되면 최근 2프레임만 남기고 두 번째 단어 판정을 새로 시작한다. 두 단어가 순서대로 확인되면 자동 통과한다. 이 두 문장은 단어 순서 판정이고, 나머지 세 문장은 문장 분류이므로 구분한다.
- 사전은 목표 단어를 정하지 않고 후보를 계속 표시하며, 손이 모두 미검출되면 윈도우와 연속 판정을 초기화한다. 학습 평가의 통과 판정과 사전의 후보 표시는 서로 다른 조건이다.
- 모델 점수는 보정된 정확도나 성공 확률로 해석하지 않는다.

### 현재 모델 버전과 학습

- `unit5.pt`: AI Hub REAL01~REAL12 기반 다섯 문장 분류 모델.
- `unit5_words.pt`: 운전·천천히·빨리 분류 모델. REAL01~REAL12 단어 자료와 직접 촬영한 두 주먹 운전 영상 3개로 추가 학습한 버전이다. 새 영상 3개와 그 파생 윈도우는 모두 train으로 사용했다.
- 운전 추가 학습에는 약 8fps로 간추린 8·12프레임 윈도우와 전체 단어 구간을 사용했다. 추론 윈도우와 학습용 윈도우를 구분한다.
- 현재 운영 AI 서비스는 기존 Level-2 저장소의 `hands-only` 소스 연결을 유지한다. 이 고급 AI 저장소에도 동일한 유닛 5 가중치와 해당 서버 코드가 반영돼 있다.
- 최종 테스트 REAL14·REAL15·REAL16·REAL18은 아직 평가하지 않았다. 아래 과거 실험의 통과율을 새 가중치의 검증 결과로 인용하지 않는다.

### Dropout 0.3 및 연속 3회 적용

단어·문장 체크포인트 모두 기존 운영 가중치에서 Dropout 0.3으로 40 epoch 추가 학습했다. 입력 투영 뒤와 풀링 뒤에 적용하며 1층 양방향 LSTM 구조는 유지한다. 추론에서는 eval 모드로 Dropout이 비활성화된다. 연속 3회 조건은 유닛 5 평가에 적용하며 사전 후보 표시는 기존 2회다. 이전 구조 비교 실험의 Dropout 0.0 결과와 구분한다. 최종 테스트는 사용하지 않았다.

## 시간 기준 윈도우 비교

2026년 11월 18일, 같은 모델과 REAL13·REAL17 검증 클립으로 9가지 조건을 비교했다. 기본 설정의 8·6·4fps 결과는 앞선 실험과 일치했다.

변경 대상은 운전/천천히와 운전/빨리의 단어 순서 판정이다. 첫 단어와 두 번째 단어 모두 최근 1초 또는 최근 1.5초 구간으로 바꿨다. 나머지 세 문장의 32프레임 구간은 기존 설정을 사용했다. 점수 기준 0.90, 연속 판정 2회, 판정 간격 2프레임, 첫 단어 확인 후 최근 2프레임 유지 조건을 적용했다.

### 비교 결과

- 4fps에서 최근 1초 구간의 전체 정답 통과는 33/50에서 42/50으로 증가했다. 운전/빨리는 0/10에서 8/10, 운전/천천히는 4/10에서 5/10으로 증가했다. 다른 문장 오통과는 0/200에서 2/200으로 늘었다.
- 8fps에서 최근 1초 구간은 정답 통과 49/50을 유지했지만 오통과가 3/200에서 5/200으로 증가했다. 6fps에서는 정답 통과가 49/50에서 48/50으로 줄고 오통과는 2/200에서 3/200으로 증가했다.
- 최근 1.5초 구간은 운전 두 문장의 정답 통과가 8fps에서 10/20, 6fps에서 8/20, 4fps에서 0/20이었다.
- 이번 실험에서는 시간 구간을 고정하면 낮은 fps의 정답 통과가 개선될 수 있음을 확인했다. 동시에 프레임을 줄여 사라진 동작 정보와 구간 구성의 영향을 독립적으로 정량화하지는 않았다.
- 세 속도 전체에서 정답 통과와 오통과를 함께 개선한 설정은 없었다. 운영 설정의 일괄 교체 근거는 확보되지 않았다.

기존과 같이 원본 30fps 가정에 따른 AI Hub 키포인트 모의 평가다. 실제 MediaPipe 웹캠·불규칙한 전송 간격·네트워크 지연은 포함하지 않았다. 최종 테스트 데이터는 사용하지 않았고 운영 설정 변경도 수행하지 않았다. 상세 기록은 [time_window_results.json](time_window_results.json), 실행 코드는 [time_windows.py](time_windows.py)에 있다.
